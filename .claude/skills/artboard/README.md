# Artboard

**Static creative, moved between aspect ratios and brands without falling apart.**

A finished ad is a *layout*, not a picture. The elements sit where they do because
of the shape of the frame. Change the frame and the layout has to be rebuilt — or
the thing that made it work stops working.

Artboard is an agent skill that treats a
ratio change as a re-layout problem: it measures what it must reuse, lifts type
and third-party logos rather than regenerating them, and remembers every
composition it studies in a library that compounds.

compositions themselves, so entries covering third-party or photographic
creatives carry their geometry and colour without redistributing the artwork.

## Why not just crop, or ask a model to reframe it?

**Cropping** cannot move an element. If the capability cards live to the right of
the hero at 16:9, they have nowhere to be at 9:16 except underneath — and getting
them there is a layout decision, not a rectangle.

**Generative reframing** garbles the things that must survive. Ask an image model
for a vertical version of an ad carrying set type and twelve third-party logos and
you get approximations of all of them. Outpainting is no better: it extends a
scene, it cannot rearrange a composition.

So Artboard splits every creative into three classes and treats each correctly:

| Class | Examples | Treatment |
|---|---|---|
| Re-authorable | Fields, surfaces, glows, spacing | Rebuild |
| Liftable | Set type, brand logos, UI, charts | Lift — never regenerate |
| Photographic | People, product, rendered scenes | Lift, reframe by cropping tighter |

## What makes it work: measure, don't estimate

Two defects sink a re-layout, and neither is visible in a thumbnail.

**Panels are almost never straight.** In the reference creative that produced this
skill, four visually identical capability cards measured **0.00°, 0.72°, 2.39° and
4.53°** — the perspective compounds down the stack. Lifted flat, the bottom two
visibly sloped. Counter-rotating each by its own measured angle fixed it; a single
guessed angle would not have.

**Every lifted element carries a rectangle of its old background.** Against a new
field that rectangle shows as a faint patch, and if the element was rotated the
patch tilts with it, which reads unmistakably as a paste-up. Feathering the alpha
removes the tell entirely.

```bash
node scripts/measure.mjs creative.png \
  --tilt "1420,1900,380,470;1420,1900,545,630" \
  --color "1660,430;1655,470"
```

```
tilt
  x1420->1900  y 380->380  slope 0.00deg  counter-rotate 0.00
  x1420->1900  y 545->551  slope 0.72deg  counter-rotate -0.72
colour
  average  #fef8f2   <- fill rebuilt surfaces with this
```

## Four jobs

- **Recut** — one creative, more ratios. The frame changes, so the layout changes.
- **Rebrand** — keep the geometry, replace palette, type, logos and copy.
- **Audit** — explain what makes a creative work, and bank it in the library.
- **Generate** — compose something new from what the library has learned.

## Install

```bash
git clone https://github.com/<you>/artboard ~/.claude/skills/artboard
cd ~/.claude/skills/artboard && npm install
```

Requires Node 18+ and [sharp](https://sharp.pixelplumbing.com/). No API keys, no
network calls, no model inference — it is arithmetic on pixels.

## Quickstart

```bash
# 1. measure
node scripts/measure.mjs ad.png --tilt "1420,1900,380,470" --color "1660,430"

# 2. adapt the worked example to your creative
cp -r examples/systo-own-operate my-recut && $EDITOR my-recut/recut-9x16.mjs

# 3. render
node my-recut/recut-9x16.mjs ad.png out-9x16.png
```

`scripts/lib.mjs` is deliberately **not** a layout DSL — every creative is laid out
differently and a general schema for "where things go" collapses on the second real
job. It gives you the operations that are genuinely hard (`lift`, `feather`,
`fadeEdges`, `place`) and you write the layout in plain code beside them.

## Delivery reality

`docs/platforms.json` carries the constraint table, with each line marked
`api-verified` (an API accepted or rejected it in a real run, message quoted) or
`documented`. The ones that most often break a plan:

- **Instagram feed crops anything taller than 4:5.** A 9:16 in feed loses roughly a
  third, top and bottom. 4:5 is the correct answer to "make it vertical".
- **Stories render no caption.** Words must be burned into the image.
- **TikTok cannot take a static image at all** — and creating a *draft* succeeds
  while only *scheduling* rejects it, so verify with the real action.
- **YouTube has no static post type.**

## The library

Every job appends to `library/`. Entries hold composition *knowledge* — grid, type
scale, sampled palette, element inventory with measured boxes and tilts, reframing
rules, what nearly broke. They hold no assets, no imagery and no copy.

Fidelity is declared per entry and never promoted without re-measuring. Only
`spec` licenses a recut without re-opening the source. Under-claiming costs one
cheap measure pass; over-claiming silently ships a crooked layout.

## Copying, and where the line is

Learning a composition is normal practice — art directors have kept swipe files
forever. Reproducing someone's assets is not.

Fine: grid, ratios, type scale, colour relationships, hierarchy, the structural
idea. Not fine: their logo, photography, illustration, copy, or anything that
would make a viewer think your creative is theirs. The library enforces this by
shape: it stores measurements and refuses assets.
